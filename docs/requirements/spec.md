# nova 需求规格

> 版本：v2.0
> 状态：**基线**（参数见 [`parameters.md`](./parameters.md)）
> 范围：Session 级可回放消息服务——多区域建会话、发 Turn、跨 Turn 流式观测与续订。

---

## 1. 系统目标

构建一个 **Session 级可回放对话流** 服务：用户可创建会话并发起多轮 Turn；执行过程产生的事件进入同一条 Session 日志；任意观察者可开屏、续订、多端同序观测。

Turn 对齐一次模型补全（类似 Responses / Messages 的一轮调用）；对外主资源是 **Session**（跨 Turn 的事件 WAL），不是单次补全对象。

### 1.1 角色

| 角色 | 描述 | 主要关注 |
|------|------|---------|
| **提交者** | 建 Session、发 Turn 的用户 | 提交成功、观测进度、断线可恢复 |
| **观测者** | 查看同一 Session 的用户（可跨区） | 内容与顺序一致、可续订 |
| **执行端**（Agent） | 领取 Turn 并写入流事件 | 领到 Turn、写入被 fence 保护 |
| **运维** | 系统运营方 | 扩缩容、故障处置、热→冷 |

### 1.2 术语

| 术语 | 定义 |
|------|------|
| **Session** | 用户可见的对话线程：元数据、占用锁、渲染快照、可回放事件日志 |
| **Turn** | 一轮用户输入 + 一次生成；领取与执行的单位 |
| **流式输出** | Turn 执行过程中持续产生的增量事件（及 Session 级信封事件） |
| **观测游标** | 客户端持有的 `(session_id, last_seq)`，用于断线后精确续订 |
| **尝试序号**（Attempt） | Turn 被领取的次数，每次领取递增；用于隔离失效持有者的写入 |
| **快照** | 带 `snapshot_seq` 的折叠开屏态（气泡、running[] 等） |
| **热层 / 冷层** | 当前可精确 resume 的流存储 / 归档存储 |

### 1.3 需求书写约定

1. 描述可观察的外部行为与必须成立的性质，不指定实现方式。
2. 每条需求配可测验收标准。
3. 类别：**功能 FR** / **正确性 CR** / **质量 SR·OR·SEC** / **约束 CON**。

## 2. 功能需求（FR）

### 2.1 Session 与 Turn

| ID | 需求 | 验收标准 |
|----|------|---------|
| **FR-1** | 多区域接入点均可创建 Session、提交 Turn | 任意区域提交，成功率与延迟无显著差异（P99 延迟差 < 200ms） |
| **FR-2** | Turn 提交异步：落库后立即返回，不等待生成完成 | `POST` 返回 202 `{turn_id}`；生成在后台进行 |
| **FR-3** | Session 占用锁：同一 Session 当前不可并行多个 Turn | 第二路 Turn 在 busy 时被拒绝或排队策略可观测；busy/idle 以流事件为准 |
| **FR-4** | 提交幂等：同一 Turn 提交意图重复到达只产生一个 Turn | 同一幂等键重放多次 → 仅 1 个 Turn |
| **FR-5** | Agent 可 pull/claim 待领取 Turn | 待领取 Turn 可被领取；领取后 attempt 递增 |
| **FR-6** | 失联或执行上界到期的 Turn 可被回收 | 强制终止 Agent 后，Turn 在回收时限内被接管或失败收口 |
| **FR-7** | 过期 attempt 的写入被拒绝 | 回收抬高 attempt 后，旧持有者 append 失败 |

### 2.2 流式观测

| ID | 需求 | 验收标准 |
|----|------|---------|
| **FR-8** | Session 流式输出可被持续观测 | 任意时刻接入可获得完整可用历史 + 后续增量 |
| **FR-9** | 观测者可在执行中途接入；开屏时间不随已运行时长增长 | 首屏走快照；P99 见 parameters |
| **FR-10** | 多用户跨区域共享观测同一 Session | 不同区域观测者内容与顺序一致 |
| **FR-11** | 观测连接中断后可精确续订 | 带 `from_seq` / Last-Event-ID 重连，无重复无遗漏 |
| **FR-12** | 客户端唯一需持久化的连接级状态是游标 `(session_id, last_seq)` | 换实例、换设备可续订；服务端无连接粘性 |
| **FR-13** | 热层已不包含所请求序号时必须明确报错 | 返回可诊断错误（如 409）并导向快照或冷层；不得静默从其它位点续发 |
| **FR-14** | 有效 Session 日志始终可恢复 | 热层卸载后仍可通过快照/冷层打开 |

### 2.3 接入与跨区

| ID | 需求 | 验收标准 |
|----|------|---------|
| **FR-15** | 对外单一会话 API（写与订同一门面） | 建 Session、发 Turn、快照、SSE 均经同一 API 契约 |
| **FR-16** | 外区写转发权威区；外区读就近并可回源 | 外区 POST 不落权威锁；外区 GET 流可见权威区已提交事件 |
| **FR-17** | 接入多实例无粘性 | 停一个实例后，客户端用同一游标换实例续订成功 |

### 2.4 过载保护

| ID | 需求 | 验收标准 |
|----|------|---------|
| **FR-18** | 超出承载时拒绝新 Turn 提交并明确告知 | 待领取或在途量达阈值时返回可重试拒绝；已接受的不受影响 |

## 3. 正确性需求（CR）

| ID | 性质 | 验收标准 | 违反后果 |
|----|------|---------|---------|
| **CR-1** | **不双领**：同一 Turn 同一时刻只被一个 Agent 持有 | 多 Agent 并发抢领，无双领 | 重复执行、输出交织 |
| **CR-2** | **提交幂等**：同一意图只产生一个 Turn | 幂等键重放（含间隔后）→ 仅 1 个 | 重复计费/重复生成 |
| **CR-3** | **输出不交织**：被回收 Agent 的后续输出不得与新 attempt 混合 | 强杀后重派，观测端无交织 | 内容错乱 |
| **CR-4** | **观测无重无漏** | 随机断连多次，与不断连对照组一致 | 内容错乱难排查 |
| **CR-5** | **因果顺序一致** | 不同观测者事件序列一致 | 协作误解 |
| **CR-6** | **Turn 不丢失**：已返回成功的 Turn 最终必达终态 | 注入故障，无永久非终态 | 任务凭空消失 |
| **CR-7** | **执行权失效后隔离**：旧 attempt 写入被拒 | 假死恢复后的写入无效 | 覆盖新结果 |
| **CR-8** | **过载不导致数据损坏** | 高压拒绝提交时无双领、无丢 Turn、无 seq 分叉 | 过载连带故障 |

## 4. 质量需求

### 4.1 规模与伸缩（SR）

| ID | 需求 | 验收标准 |
|----|------|---------|
| **SR-1** | 接入可水平扩容，无连接粘性 | 实例数增加，吞吐近线性；换实例可续订 |
| **SR-2** | 同 Session 订阅者不放大后端对上游 stream 的订阅数 | 实例内复用一路订阅再扇出 |
| **SR-3** | 支持分钟～小时级长 Turn | 长 Turn 不被误判超时（在上界内） |
| **SR-4** | 跨区观测带宽不随该区观测者线性增长于源区 | 就近接入 + 回源/副本策略可控 |

### 4.2 运维（OR）

| ID | 需求 | 验收标准 |
|----|------|---------|
| **OR-1** | 组件故障可恢复 | 接入、Agent、存储单点故障有恢复路径 |
| **OR-2** | 降级状态对用户可见 | 不静默呈现陈旧数据 |
| **OR-3** | 关键不变量有监控 | 双领、丢 Turn、热 miss、饥饿式停滞有指标 |
| **OR-4** | 规模逼近适用区间上限时提前告警 | parameters 各维度有阈值告警 |

### 4.3 安全（SEC）— 本期最小集

| ID | 需求 | 验收标准 |
|----|------|---------|
| **SEC-1** | 身份认证（可后期细化） | 未认证请求被拒绝 |
| **SEC-2** | 防滥用：连接数与提交限流 | 单用户无法耗尽系统资源 |

> 完整鉴权票、出口脱敏、多租户等见后续设计；本期不阻塞流式主轴。

## 5. 需求冲突与取舍

| # | 冲突 | 仲裁 |
|---|------|------|
| **X1** | 流式保留成本 × 可恢复性 | 热→冷；有效 Session 始终可订；热 miss 明确报错 |
| **X2** | 跨区低延迟读 × 单权威写 | 写转发权威区；读就近回源（一期）；Mirror 实测触发 |
| **X3** | POST+SSE 同进程简单 × 故障域/独立扩缩 | **一期同进程**（Tokio 下长连接不默认拖死 CAS）；拆进程为实测触发的部署选项 |
| **X4** | 提交延迟 × 持久化 | 返回成功前必须已进入可领取持久状态 |

## 6. 本期范围界定

| # | 议题 | 本期 | 说明 |
|---|------|------|------|
| **S1** | 容量感知匹配 / 装箱 / 任务池 | **不做** | 已移出产品范围 |

| **S6** | 生产热层产品 | mem 验证；Redis Streams 为后续适配器 | L0–L2 不依赖 Docker |

## 7. 验收总览

落地以分层验证为准（见 [`../plans/`](../plans/)）：`just verify`（全量；可指定 `l0|l1|l2`）+ 人工 `just sim`。

| 类别 | 重点场景 |
|------|---------|
| 开屏 + 续订 | 快照 → SSE `from_seq`；断线重连无重无漏 |
| 多订 | 同 Session 两观察者顺序一致 |
| fence | 杀 Agent → reaper → 旧 attempt 被拒 |
| 跨区 | 外区 POST 转发；外区 GET 回源 |
| 无 sticky | 换 api 实例续订 |
| 热 miss | 明确错误 → 快照/冷层 |
