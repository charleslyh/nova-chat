# 设计 04 · 内容完整性

> 依据：FR-39, CR-13, INV-44, SEC-4 · [D20](../architecture/decisions.md#d20-交付边界收口存储与订阅分离) ⑧

---

## 1. 职责已降级为「防篡改」

早期方案中，指纹承担「纠纷定责且不构成存储原文」的双重角色。**存原文之后该叙事作废**：纠纷直接调原文即可。

指纹现在只做一件事：**检测存储层篡改**。

明确**不是**什么：

| 不是 | 原因 |
|---|---|
| 不可否认性证明 | 密钥在服务端，服务端可自行生成任意标签 |
| 「未存储原文」的证据 | 原文就在库里 |
| 访问控制 | 那是租户校验的职责 |

写清这一点是为了避免将来有人依赖它做定责。

---

## 2. 规范化是前提，不是优化

没有规范化，指纹**不可用**：同一逻辑内容两次序列化可能在键序、空白、Unicode 组合形式上不同，导致**误报**。

| 规则 | 处理 |
|---|---|
| 对象键序 | 按字节升序排序 |
| 空白 | 紧凑分隔符，无多余空格 |
| Unicode | 全部字符串归一为 **NFC** |
| 控制字符 | 显式转义为 `\uXXXX` |
| 数字 | 由 `serde_json::Number` 稳定输出 |

### 2.1 增量拼接必须先合并后归一

```rust
pub fn canonical_output_text<'a, I: IntoIterator<Item = &'a str>>(deltas: I) -> String {
    let joined: String = deltas.into_iter().collect();
    nfc(&joined)     // 一次，对整体
}
```

**逐片归一是错的**：跨越两个增量的字素（例如 `"cafe"` + `"\u{0301}"`）会与合并后的文本归一出不同结果，产生虚假的完整性失配。

该性质由单测 `delta_chunk_boundaries_do_not_affect_the_fingerprint` 固定，覆盖三种切分方式（整体 / 词中切 / **字素中切**）。

## 3. 方案

| 项 | 取值 |
|---|---|
| 算法 | HMAC-SHA256 |
| 标记 | `hmac-sha256-v1`（随记录保存，供轮换识别） |
| 签名输入 | `canonical_items(input) + "\|" + canonical_items(output)` |
| 比较 | `subtle::ConstantTimeEq` |
| 密钥来源 | **仅环境变量** `NOVA_INTEGRITY_KEY`，≥ 16 字节 |

### 3.1 为何实现放在领域层

`HmacSha256Integrity` 位于 `crates/core`，而非各适配器内。

它是纯计算、无 I/O，不属于「承载产品」。更关键的是：**若在 mem 与 sql 各写一份，两者会漂移**，表现为切换后端后出现虚假失配。一份实现从构造上排除该风险。

### 3.2 常数时间比较不是形式主义

短路比较会按字节泄露期望标签：攻击者通过测量响应延迟可逐字节猜出标签。故用 `ct_eq`。

## 4. 密钥生命周期

| 阶段 | 行为 |
|---|---|
| 启动 | 从环境变量读取；**启用校验但密钥缺失时启动即失败** |
| 配置文件 | 只出现**变量名**，绝不出现值（SEC-4） |
| 轮换 | 新密钥 + 新 `alg` 标记；旧记录以旧标记验证。**本期未实现多密钥并存** |
| 日志 | 禁止记录密钥（SEC-9） |

### 4.1 为何启动即失败而非降级

若密钥缺失时静默跳过签名，服务看起来正常，但写入的记录**永远无法验证**。这比不启动糟糕：故障被推迟到未来某次审计，且已污染的数据无法追溯。

---

## 5. 校验失败处置

```
读取 → 重算标签 → 比对
  ├─ 一致 → 正常返回
  └─ 不一致 → ContextError::IntegrityMismatch → 500 + 计入指标
```

**不返回可疑内容**。失配意味着存储层已不可信，返回内容等于把污染数据交给调用方。

指标 `integrity_mismatch` 应配告警：单次失配可能是硬件问题，连续失配意味着存储层被篡改。

### 5.1 走链时逐环校验

`resolve_chain` 对每一环调用 `verify`。代价是每次拼接多算 N 次 HMAC（数 KB 内容约微秒级，见 `parameters.md` §5.1），换取的是**被篡改的历史不会进入模型上下文**。

---

## 6. 开销

| 项 | 量级 |
|---|---|
| 规范化 + HMAC（数 KB） | < 1ms（微秒量级） |
| 每次生成签名次数 | 2（创建时 + 终态时） |
| 每次走链校验次数 | 链深度 |

在 70/s 峰值下可忽略。这也是为何默认开启：默认关闭会让「有校验」变成例外而非常态。
